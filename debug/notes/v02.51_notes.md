# v02.51 — 门校验 + 崩溃免疫迷你现场（log74 判决的修复版）

版本串：`J2ME Player v02.51 b455 (5a5b109)`（VM 侧 80e20a4）
VPK：`out/vpk/midp_vita_v02.51.vpk`，md5 `774f0290266caff1e8f70f36a3655041`

## 一、log74 判决（为什么改）

v02.50 四种设计结局一个没出现，进程崩成 psp2core（第五种结局）：

1. **刹车确实触发了**——崩溃现场=精确环模板（fp=0、r5=gp、
   r6=0x81edf004、[sp]=pad、其余 4 线程全在内核睡眠）。六轮历史证明
   这个环本身永不崩溃，v02.50 唯一新增跳转就是 `bx [r6]`。
2. **门是坏的**——`[r6]`=0x81edc2d4 是 Java 堆对象（class 字指向模块
   ROM 区、含自引用），不是 lw_exit。`bx` 后在堆上执行对象数据当指令，
   跑到 0x81ee0dd8（=门对象+0x2d04）全零页致命故障。r0≠pc 证明垃圾
   "代码"执行了若干条后才死。
3. **取证全灭**——崩溃快过 watchdog 250ms 轮询（最后心跳到 coredump
   仅 ~76ms），无 BRAKE 行；psp2dmp 从不映射 BSS，hist 四元组/flood
   现场/**cpe 探针答案**随进程死亡。v02.50 文档风险 1 精确应验。

## 二、洋葱新层：根本不存在出生模板

log73 已证 id4 是 entry-less、fp=0、**从未出生**的线程；本轮 [r6] 装着
堆残留而非 lw_exit，以最强形式确认 v02.44 的怀疑：**蹦床读的"退出表"
不是 setup_stack_asm 留下的出生帧——那个帧从未存在**。环的本质=一个
从未出生的线程被 q5 CYCLE 派发，在未初始化的栈顶块上弹跳。刹车的
前提（"出生模板 [r6]=lw_exit"）从根上不成立。

## 三、改动（A 门校验 + B 迷你现场）

### A. 门校验（InterpreterRuntime_arm.cpp，trip 路径）

`bx` 前用 `movw/movt` 装入 `_ZN9JVMThread23lightweight_thread_exitEv`
真实地址与 `[r6]` cmp：
- 匹配 → 照常 BRAKE（brakes++、预算 8、tripped=2、bx）
- 不匹配 → **park 兜底**（tripped=1，v02.48 已验证行为），永不再跳垃圾

证据落点：`flood[16]`=门词原值、`flood[17]`=verdict（1 好/0 坏），两个
dump 站点（ring_trap 头 + v250 行）都打印。

签名保险：`R_ARM_MOVW_ABS_NC/MOVT_ABS` 重定位绑定 mangled 符号——
JVMThread 布局变更会使**链接失败**而非运行时静默错比。

### B. 崩溃免疫迷你现场（同文件，门判定之前）

trip 时把 6 词写到 `[sp-0x40..sp-0x28]`（C 栈页 0x81641000/256K——
log74 已证 psp2core **必然带上**此页）：

| 偏移 | 内容 |
|---|---|
| +0 | magic `0x56353144`（'V51D'，扫描锚点） |
| +4 | `[r6]` 门词（trip 时实际值） |
| +8 | `[r6+4]`（=810ebae4-static lw_exit+0x94 槽） |
| +12 | `[r6+8]`（=810eba24-static） |
| +16 | `[r6+16]`（蹦床第 7 条指令读的 TestCompiler 槽） |
| +20 | cpe（=flood[14]，**悖论答案崩溃也丢不了**） |

今后任何崩溃：psp2dmp `mem` 扫 0x8167fd** 区找 magic，直接读门四词
+ cpe。
